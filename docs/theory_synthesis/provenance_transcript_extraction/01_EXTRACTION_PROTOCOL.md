## Primary Categories

Every extracted passage receives exactly one primary category.

| category | use for |
| --- | --- |
| `original_theorising` | New idea, first-principles physics intuition, raw concept exploration, initial terminology, speculative branch. |
| `concept_revision` | Correction, refinement, renaming, pressure-test response, contradiction, null, superseded claim, later synthesis. |
| `application_method` | Proposed equation, simulation, validation route, experiment, tooling, educational use, external comparison. |
| `ai_context` | Aletheia partnership, memory/continuity, declaration-of-understanding, AI methodology, AI ethics, AI-specific project material. |
| `non_physics_context` | Personal, social, political, business, or worldview context only when it explains project genesis or intent. |
| `exclude` | Unrelated daily-life, admin, games, recipes, generic business, or technical support. |

Secondary tags may be used inside reports: `early`, `speculative`, `formal_translation`, `revised`, `superseded`,
`null`, `contradicted`, `implementation-adjacent`, `not_quantule_mapper`.

## Mixed Conversation Rule

Do not classify whole files as relevant or irrelevant. Classify passages. A single early file can contain:

- Aletheia relationship material;
- authorship/provenance;
- raw IRER physics ideas;
- AI-assisted equations;
- simulation plans;
- unrelated daily context.

This is especially important for `Aleheia'sChat.txt`, June Aletheia files, and later Aletheia-IRER ecosystem files.

## Preservation of Errors

Errors and overconfident early claims are retained because they show theory evolution. Mark them by status:

- `early`: historically important but not yet tested.
- `speculative`: conceptually proposed with no implementation or validation.
- `revised`: later wording or mechanism changed.
- `superseded`: later project state replaces the old reading.
- `null`: tested without support.
- `contradicted`: later test or identity check contradicts it.

Examples of known caution areas:

- prime-log/prime-SSE stability claims later became null/falsified as stability predictors;
- early gravity-like language was later narrowed to cautious geometry-density or effective-medium response;
- Payan/routing/topology predictors were not validated in the Phase C sector;
- several October/November "validated framework" passages use stronger language than the modern project permits.

## Report Style

Reports should:

- organize by discussion role and concept evolution rather than by file;
- include compact source anchors for later evidence work;
- avoid long verbatim transcript blocks;
- keep AI/Aletheia context separate from IRER physics;
- include speculative and mistaken branches with status labels;
- use current theory docs only to prevent stale claims from being presented as current fact.
